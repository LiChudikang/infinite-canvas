# 在线视频模板平台（首版待验收）

入口为 `/studio`，也可从原有“视频工作流模板”页面进入。作者在画布制作模板，使用者在独立页面选模板、填文字、上传图片，再使用自己的方舟渠道生成。用户无需连接本地 Agent；服务端复用 Seedance 执行器。

目前提交的是可配置运行的实现，尚未部署或进行真实收费生成、浏览器完整验收。模板库不会自动带入作者浏览器中的模板；需要作者逐个发布。

## 已实现范围

- 受邀账号访问：作者分发独立访问凭证，服务端配置 `author` / `user`。所有作者角色具有全平台发布权限；尚无公开注册或多租户作者空间。
- 多模板分类、可选样片链接、固定版本分享链接、文字和图片变量表单。使用者看不到完整提示词与固定执行参数。
- 从本地已发布模板选择版本上架：编译现有横向 Seedance 流程，保存固定镜头与必要参考图片，不传生成视频或历史任务。样片需单独提供可分享的 HTTPS 地址。
- 用户自行配置方舟 API Key，AES-256-GCM 加密保存，密钥由运行环境提供。凭证不在模板或任务快照中，任务记录只保存凭证版本；轮换渠道后旧任务仍使用原版本。
- 任务按用户隔离，服务端从固定模板版本组装请求，拒绝额外参数。重复 requestId 返回同一任务，提交结果不明时保留记录，不能静默再收费。
- 我的作品、手动刷新进度、原片和成片下载、已有任务继续查询/合成、字幕校对与再做一个。

首版只支持现有方舟 Seedance 模型和工作流范围，不支持任意中转站或其他视频提供商。用户账户须能调用模板中的固定模型。保存 Key 不验证余额或权限，也不触发生成。

## 服务端启动

在运行服务器准备 Node.js、项目依赖和 FFmpeg。自动字幕还需现有工作流要求的 Python 与识别模型；参考 [Seedance 工作流](seedance-local-workflow.md)。前端静态站点与本接口使用同源代理，外部访问时配置 HTTPS。

在仓库的 `data/platform/`（已被 Git 忽略）或仓库外的受保护目录中创建账号文件，例如结构如下。示例占位值必须替换，每个账号使用独立的随机访问凭证：

```json
[
  { "id": "owner", "role": "author", "token": "REPLACE_WITH_AUTHOR_ACCESS_TOKEN" },
  { "id": "guest-a", "role": "user", "token": "REPLACE_WITH_USER_ACCESS_TOKEN" }
]
```

账号文件权限应设为 `600`。访问凭证属于登录凭证，不是生成渠道 Key。作者把模板链接和接收者自己的凭证分别交付，切勿把凭证放进 URL。

运行环境需要：

| 变量 | 含义 |
| --- | --- |
| `PLATFORM_ACCOUNTS_FILE` | 账号 JSON 的绝对路径 |
| `PLATFORM_DATA_DIR` | 模板、任务和加密渠道文件的绝对目录 |
| `PLATFORM_ENCRYPTION_KEY` | 32 字节随机密钥的 64 位十六进制编码，通过部署环境注入，不提交 Git |
| `PLATFORM_PORT` | 本机接口端口，由部署者选择 |
| `PLATFORM_GENERATION_ENABLED` | 显式设为 `true` 才允许用户确认生成；默认关闭 |
| `FFMPEG_PATH` | 可选；未配置沿用现有执行器的 `ffmpeg` |
| `WORKFLOW_PYTHON` / `WORKFLOW_WHISPER_MODEL` | 自动字幕模板所需 |
| `WORKFLOW_FONT_FILE` | 可选字幕字体路径 |

保护并备份加密密钥；丢失后已有渠道凭证不能解密。任务执行完全使用对应用户的渠道，不回退到服务器 `ARK_API_KEY`。当前凭证历史会保留供旧任务续查，尚未实现渠道删除、保留期限或密钥轮换管理界面。

```bash
cd canvas-agent
npm install
npm run platform
```

服务器只监听 `127.0.0.1`，通过站点反向代理转发 `/api/platform/`。不要暴露原本机 Agent 管理接口。服务进程需要单实例运行和持久化目录；当前没有分布式任务队列或自动故障接管。

## 前端开发与部署

本地开发时，在启动前端的环境中设置 `PLATFORM_PROXY_TARGET` 为本机平台接口地址，例如 `http://127.0.0.1:<你配置的端口>`，再运行现有 `web` 开发命令。`web/vite.config.ts` 会代理 `/api/platform`；变量变更后需重启开发服务。

正式部署中，静态站点需要为 `/studio` 和子路径提供 SPA 回退，并将 `/api/platform/` 单独反向代理到接口服务。Vite 开发代理不会进入静态构建。现有 Docker / Render 一键部署没有自动配置此新服务。

请求体沿用 Agent 的 **30 MB** 上限，包含 base64 图片；超出返回 413，用户缩小图片后重试。未新增并发、调用重试或任务超时数值；执行器沿用现有行为。对外扩大使用前，需单独明确资源容量、用量控制和数据保留策略。

## 作者与使用者流程

1. 作者在画布中调好一个受支持的 Seedance 流程，文字使用 `{{brand_name}}` 等变量，选择可替换图片，发布为本地模板。
2. 作者进入 `/studio`，使用作者访问凭证登录，在“发布模板”选择本地版本、填写分类和可选样片链接，上架并复制链接。
3. 接收者用自己的访问凭证打开链接，在“我的渠道”保存自己的方舟 API Key。
4. 使用者返回模板，上传图片和填写文字，确认预计调用次数及自付费用，生成任务。
5. 在“我的作品”手动刷新进度；自动字幕模板需校对后合成，成片可下载或再做一个。

指定版本不存在会明确失败，不会回退最新版本。已发布版本不可覆盖；先在画布发布新版本，再上架。没有预置虚构模板或样片。

## 已验证与待验收

模拟测试命令：

```bash
cd canvas-agent
npm run test:platform
./node_modules/.bin/tsx --test src/workflow/seedance.test.ts
```

本次平台 5 项、原执行器 6 项模拟测试通过，未调用真实供应商。按项目约定未执行构建或语法检查。

待验收：双浏览器受邀访问、发布两个不同模板、移动端素材表单、真实方舟账户权限、跨镜头效果、字幕校对、最终视频下载、服务重启后续查及正式反向代理部署。

已保留但未启动的任务显示“待作者检查启动状态”，不会自行重建；作者需检查持久化记录和服务依赖。对于未提交镜头、明确失败或提交结果不明的任务，首版不会通过用户“继续”按钮重新发起收费提交，后续需补作者诊断、已有任务 ID 接回和明确确认的单段重试。
